  описании объекта закупки 10 позиций «Запасные части», у каждой — подзаголовок оборудования («Насосный агрегат

  у всех строк одного номера оказались одни и те же наименование, артикул и НМЦ (верной была только поз. 8).
  Нужно (пользователь): 10 позиций с наименованием по оборудованию, детали — состав / характеристики позиции.
- `prompts.INVENTORY_RULES`, п. 2а: такая строка — одна позиция; name — подзаголовок оборудования дословно (не
  «Запасные части»), одинаковое оборудование под разными номерами — разные позиции; количество только у вложенных
  строк — qty «1», unit «компл.»; «Итого» — не позиция.
- `prompts.DETAIL_RULES`: tz такой позиции — заголовок оборудования и все вложенные строки по порядку
  («N. деталь — арт. … — кол-во ед.», без объединения повторов), в конце «Всего по позиции»; brand_model — марка и
  модель оборудования из подзаголовка.
- НМЦК такой позиции — сумма строк обоснования НМЦ по её деталям (у К952 в разделе 6 детали идут сплошной
  нумерацией 1–103, повторы артикула внутри позиции сложены: «Шпонка 807010 — 2», одинаковые детали разных позиций
  тоже бывают сложены: «Ротор 4436002 — 2» — поз. 4 и 9; тогда — цена за единицу × количество в позиции).

  повторов; не помогло — строки одного номера склеиваются в одну позицию (`_merge_duplicates`), в проверках —

- Сверка с другими документами (обоснование НМЦ, форма КП, договор; пользователь 27.11.2026: «сравнивал
  наименование из спецификации из ТЗ с НМЦК… сверить количество поставляемого оборудования, состав не нужен»):

  наименованию (одинаковое оборудование под разными номерами — по порядку). В «Примечание»: «⚠ Наименование
  отличается: …», «⚠ В документе … эта позиция под № …», расхождение количества — как раньше. Документ, где строк
  другое число и меньше половины позиций нашлись по наименованию (перечисляет состав — детали поштучно, как
  раздел 6 К952), не сверяется: «⚠ Документ … количество с ним не сверялось» вместо десятков ложных расхождений.
  Модели: такой документ в other_sources не выписывать, сказать в notes. Детали между документами не сверяются.
- Правки промтов клиентов / юр. лиц в админ-панели («Перечень позиций», «Позиции подробно») новых правил не
  получают — у них свой текст.

## 0.44.4 — 27.11.2026 — Dropbox на сервере: новая папка с длинным именем не останавливает сверку
- Повод: на сервер пришли не все новые папки из Dropbox (нет К951).
- `dropbox/sync.sh`: список пропускаемых длинных имён (0.44.1) строился только перед полной сверкой; новая папка
  или файл длиннее 230 байт, появившиеся позже, роняли каждую обычную сверку — новое не приходило. Теперь после
  неудачной сверки фильтры пересобираются; изменились — следующая сверка полная.
- Отдельно проверить: `TENDERS_DIR` в `.env` сервера — сайт должен брать конкурсы из `/opt/supplybro-dropbox/Агент`,
  а не из старой копии `/opt/supplybro-tenders` (туда Dropbox ничего не кладёт). 27.11.2026 так и оказалось
  (К951 был в `/opt/supplybro-dropbox/Агент`, сайт его не видел). Теперь `run.sh` (с профилем dropbox) и «Сервер -
  состояние» громко предупреждают, если `TENDERS_DIR` не совпадает с `DROPBOX_DIR/DROPBOX_FOLDER`.
- Локальная копия (пользователь 27.11.2026: «чтобы и на локальной машине коннектился к Dropbox»): папки конкурсов —
  тем же контейнером dropbox, что на сервере (`COMPOSE_PROFILES=dropbox`, `DROPBOX_DIR=/home/user/supplybro-dropbox`,
  `TENDERS_DIR=…/Агент`), вместо застывшей копии `data/tenders` (она не удаляется). «Подключить Dropbox.bat» —
  вход в учётную запись Dropbox агента один раз. `MAIL_POLL_MINUTES=0` — опрос почты выключен (`mail_inbox.poller`):
  почту читает только сервер, иначе ответы поставщиков ложились бы в общие папки дважды.
- «Предложения поставщиков» без единого предложения (пользователь 27.11.2026, К951: «возможности редактировать нет»):
  вместо таблицы была только надпись «Предложений пока нет» — без ✏ у позиций нельзя было поправить бренд / страну
  и внести цену вручную. Теперь `renderOffers` показывает надпись и под ней таблицу позиций с ✏ (без колонок
  поставщиков и итога); кнопка «Записать в NocoDB» видна, если есть позиции.
