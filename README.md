# SupplyBro — локальный сайт

Сайт для работы с конкурсами. Работает в контейнерах Docker внутри Ubuntu (WSL),
открывается только на этом компьютере: http://127.0.0.1:8000

Что на странице сейчас:
- выбор клиента → юр. лица → конкурса (записи «Реестра конкурсов» NocoDB + папки конкурсов в Dropbox);
- **документы конкурса**: загрузка перетаскиванием в папку конкурса в `Dropbox\Агент`, автоматическая
  подготовка (распаковка архивов, конвертация .doc/.xls, текст, распознавание сканов), список файлов
  со статусами, просмотр извлечённого текста, пометки ⚠ о скрытом тексте и обращениях к ИИ;
- кнопка «+ Новый конкурс» — папка по шаблону «К---» со следующим внутренним номером, тендерная документация
  загружается в той же форме и сразу обрабатывается;
- **анализ документов ИИ**: поля конкурса (блоки 1–7) с цитатами из документов, позиции спецификации с ТЗ и ошибками ТЗ,
  проверки (нумерация, количество между документами, сумма к НМЦ), перепроверка важных полей второй моделью (DeepSeek),
  запись в NocoDB — «Реестр конкурсов» и таблица спецификации;
- карточка конкурса из NocoDB (по представлениям ролей) и его спецификация.

В NocoDB пишет только анализ. Чужие записи (двойник по номеру закупки, запись агента) сайт без подтверждения не меняет.

## Запуск двойным щелчком (Windows)

- **«Запустить SupplyBro.bat»** — поднимает Ubuntu, собирает и запускает сайт, открывает его в браузере.
  Окно закрывается само, сайт работает в фоне до перезагрузки компьютера.
  При первом запуске один раз добавляет в `%USERPROFILE%\.wslconfig` строку `instanceIdleTimeout=-1`
  (чтобы Ubuntu не выключалась сама, когда её окна закрыты) и перезапускает Ubuntu.
- **«Остановить SupplyBro.bat»** — останавливает сайт.
- **«Добавить в автозагрузку.bat»** (запустить один раз) — сайт будет подниматься сам при входе в Windows:
  свёрнутым окном, без вопросов и без браузера; программу-прокси ждёт до 2 минут.
  **«Убрать из автозагрузки.bat»** — отменить.

Перед запуском должна быть включена программа-прокси Windows (127.0.0.1:10809) — файл это проверит.
Ярлык на рабочий стол: правый щелчок по файлу → «Отправить» → «Рабочий стол (создать ярлык)».

## Запуск вручную (в Ubuntu)

```bash
cd /mnt/c/ClaudeProject/supplybro     # папка проекта
bash run.sh                           # собрать и запустить
```

`run.sh` сам создаст `.env` из `.env.example` (или допишет в него новые настройки) и папку данных.
Первая сборка после появления LibreOffice и распознавания текста — 5–15 минут, дальше — секунды.

## Каждый день

| Что | Команда |
|---|---|
| Запущены ли сайт и обработчик | `docker compose ps` |
| Журнал сайта | `docker compose logs -f web` |
| Журнал обработчика (документы, анализ, NocoDB) | `docker compose logs -f worker` |
| Пересобрать и перезапустить после правки кода | `bash run.sh` |
| Остановить | `docker compose down` |

## Как обрабатываются документы

1. Файлы загружаются на сайте (или кладутся вручную) в «Конкурсная документация» / «Разъяснения заказчика»
   папки конкурса. Сайт ставит задачу в очередь; обработчик (`worker`) берёт её.
2. Архивы распаковываются рядом с архивом в «<имя>_extracted» (как делал агент), уже распакованные не трогаются.
3. `.doc/.xls/.rtf/.odt` конвертируются в `.docx/.xlsx` (копия в `AIExtract\_converted`, исходник не меняется).
4. Из каждого файла извлекается текст: Word — с номерами пунктов (автонумерация), Excel — построчно,
   PDF — по страницам; страницы без текста и картинки распознаются (русский + английский).
   Скрытый текст (скрытый шрифт, белые буквы, крошечный кегль, скрытые листы/строки) — отдельно, в анализ не идёт.
5. Тексты — в `AIExtract\text\*.md`, список файлов — `AIExtract\text\_manifest.json`, фрагменты для поиска — в базе сайта.

## Как работает анализ

1. Если документы загружены через сайт, анализ запускается сам после их подготовки (`AUTO_ANALYZE=1` в `.env`).
   Иначе — кнопка «Запустить анализ» в блоке «Анализ документов». Анализ платный (Claude и DeepSeek по API).
2. Claude читает тексты всех документов (без скрытого текста) и заполняет поля по правилам старого агента;
   у каждого поля — документ и дословная цитата, программа проверяет, что цитата действительно есть в документе.
3. Позиции: сначала полный перечень, затем подробности частями по 10 позиций. Программа проверяет нумерацию,
   количество между документами (ТЗ, форма КП / структура НМЦ, договор) и сумму НМЦК к начальной цене.
4. DeepSeek независимо находит важные поля (цена, даты, количество, оплата, срок поставки); расхождения
   перепроверяются: ✅ — совпало, 🔺 — расхождение, оставлено перепроверенное значение.
5. Результат — в папке конкурса (`AIExtract\analysis.json`, `Позиции_и_цены.xlsx`, XML) и в NocoDB.
   Если в NocoDB уже есть такой конкурс под другим номером или запись заполнена агентом — сайт ничего не меняет
   и показывает кнопку «Записать всё равно».

Настройки в `.env`: `CLAUDE_MODEL` (по умолчанию `claude-sonnet-5-5`), `CLAUDE_EFFORT` (`medium`),
`DEEPSEEK_MODEL` (`deepseek-flash`), `AUTO_ANALYZE`, `NOCODB_WRITE`. После правки `.env` — `bash run.sh`.
   Повторно обрабатываются только новые и изменённые файлы.
6. Испорченные имена файлов из архивов («Па®ЂЃ¶•≠®•») на сайте показываются исправленными; файлы не переименовываются.

## Где что лежит

- Код — `app/`: `main.py` (адреса сайта), `worker.py` (обработчик), `docs/` (подготовка документов),
  `tenders.py` (папки конкурсов), `nocodb.py` (чтение NocoDB), `db.py` (база и очередь), `static/` (страница).
- `tools/extract_archive.py` — распаковка архивов (копия из проекта StrokTenderDataExtractor).
- Клиенты и юр. лица — `config/clients.json` (`tenders_folder` — папка клиента в `Dropbox\Агент`).
- Настройки запуска — `.env` (в GitHub не попадает), образец — `.env.example`.
- Ключи — папка `secrets/` (в GitHub и в образ не попадает).
- Данные сайта (база, очередь) — `DATA_DIR` внутри Ubuntu (по умолчанию `/home/user_1/supplybro-data`).
- Документы конкурсов — `TENDERS_DIR` (`Dropbox\Агент`).

## Сеть

- Сайт виден только на `127.0.0.1` этого компьютера.
- На этом компьютере (`compose.local.yml`) контейнеры работают в сети Ubuntu и ходят в интернет
  через прокси Windows (`OUTBOUND_PROXY`, сборка — `BUILD_PROXY`; пакеты Debian — с зеркала `APT_MIRROR`).
  Если прокси выключен, страница покажет «нет связи с NocoDB».
- На сервере: в `.env` убрать `COMPOSE_FILE` и оставить прокси пустыми — сработает только `compose.yml`.
